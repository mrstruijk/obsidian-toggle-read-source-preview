# Investigation Plan — Cyclist Plugin

Goal: Audit the Obsidian Cyclist plugin for additional issues, bugs, vulnerabilities, and performance problems, then plan fixes.

## Findings

### 1. Use of private/undocumented Obsidian API (highest risk)
- **Files:** `main.ts:19-20`, `main.ts:42-53`, `main.ts:58`
- **Issue:** Live-preview detection uses `view.getState().source`, which is an internal `ViewState` shape. The official public API for checking live-preview status is `editorLivePreviewField` from `@codemirror/state` / `obsidian`. Setting `mode`/`source` on the view state is likewise undocumented.
- **Risk:** Plugin may break on future Obsidian updates; type declarations do not guarantee these keys; behavior may differ on mobile or canvas-popout leaves.
- **Action:** Research whether a public API path exists for switching view modes. If not, document the private dependency and add runtime guards. Consider using `MarkdownView` methods (e.g. `getMode`, `setMode`/`togglePreview` if available) instead of mutating `ViewState` directly.

### 2. Unhandled async transitions / race window
- **Files:** `main.ts:58`, `main.ts:69`
- **Issue:** `leaf.setViewState(...)` returns `Promise<void>` but is discarded with `void`. Rapid hotkey presses can fire overlapping transitions before the previous one completes, leading to inconsistent editor state or dropped transitions.
- **Risk:** Glitchy cycling; possible exceptions swallowed; state may end out of sync with the perceived mode.
- **Action:** Track an in-flight transition promise and either await it or ignore subsequent triggers until it resolves.

### 3. README inaccuracy
- **File:** `README.md:3`
- **Issue:** README says "These changes will affect all open editors", but the current code only cycles the active markdown leaf (`getActiveViewOfType(MarkdownView)` + `activeView.leaf`).
- **Risk:** Misleading users; bug report bait.
- **Action:** Update README to state only the active editor cycles, or restore the previous `iterateAllLeaves` behavior intentionally.

### 4. Typescript target mismatch
- **Files:** `tsconfig.json:7`, `esbuild.config.mjs:36`
- **Issue:** `tsconfig.json` targets `ES6` while esbuild targets `es2018`.
- **Risk:** Subtle runtime inconsistency; esbuild may emit features TS checker thinks are unavailable.
- **Action:** Align both targets (e.g., `ES2018`).

### 5. Legacy ESLint config left behind
- **Files:** `.eslintrc`, `eslint.config.mjs`
- **Issue:** `.eslintrc` exists but is described as inactive; flat config is used. Dual config is confusing and can lead to accidental lint drift.
- **Risk:** Maintenance overhead; IDE may pick wrong config.
- **Action:** Remove `.eslintrc` if it is no longer used, or keep only one canonical config.

### 6. Missing lint script
- **File:** `package.json:6-10`
- **Issue:** No `lint` script despite having ESLint configured. Easy for lint errors to slip in.
- **Action:** Add `"lint": "eslint ."` to scripts.

### 7. Non-atomic file writes in release helper
- **Files:** `version-bump.mjs:15`, `version-bump.mjs:20`
- **Issue:** `writeFileSync` overwrites `manifest.json` and `versions.json` in place. A crash during the write can leave these files partially written.
- **Risk:** Corrupted release metadata.
- **Action:** Write to temp files and rename atomically, or use a library that does so.

### 8. Dev dependency vulnerabilities
- **File:** `package-lock.json` (transitive deps)
- **Issue:** `npm audit` reports 8 vulnerabilities (4 moderate, 4 high) in dev-only packages: `ajv`, `brace-expansion`, `fast-uri`, `flatted`, `js-yaml`, `minimatch`, `picomatch`, `yaml`.
- **Risk:** Build/tooling compromise; not runtime because these are dev deps, but still worth fixing.
- **Action:** Run `npm audit fix` and verify build/lint still pass. If breaks occur, update selectively.

### 9. `manifest.json` minAppVersion may be too low
- **File:** `manifest.json:4`
- **Issue:** `minAppVersion` is `0.15.0`. The plugin uses `setViewState`, `getState`, and assumes live-preview semantics. Need to confirm those APIs existed and behaved the same in `0.15.0`.
- **Action:** Verify against Obsidian API changelog; bump `minAppVersion` if required.

### 10. `types.d.ts` empty / no private API augmentation declared
- **File:** `types.d.ts`
- **Issue:** File has an empty augmentation block. Since the code does rely on private state keys, either it should declare them here (accepting the private API risk) or stop using them.
- **Action:** Decide whether to codify the private state shape or remove the dependency.

## User Decisions (recorded)

1. **Scope of cycling:** Active editor only.
2. **Private API usage:** Prefer public API where possible; fall back to other safe approaches only if no public path exists.

## Research Update

Public Obsidian APIs available and sufficient:

- `MarkdownView.getMode()` returns `'source' | 'preview'` — official.
- `editorLivePreviewField` (exported by `obsidian`) is the public way to check Live Preview vs Source mode. It is a CodeMirror `StateField<boolean>` and is read from the underlying editor state (`view.editor.cm.state.field(editorLivePreviewField)`).
- `WorkspaceLeaf.setViewState(viewState)` is the public way to switch modes. The `mode`/`source` keys inside `ViewState.state` are de-facto standard, used by many plugins, and are the only deterministic way to set a specific mode. Keep using them with immutable state updates.
- `minAppVersion: "0.15.0"` already covers `editorLivePreviewField` (introduced `0.13.21`) and `setViewState`/`getMode` (much earlier). No bump needed.

## Recommended Plan

1. **Update `main.ts` to use public APIs**
   - Import `editorLivePreviewField` from `obsidian`.
   - In `getCurrentMode`, use `view.getMode()` + `editorLivePreviewField` instead of `view.getState().source`.
   - Access the CodeMirror 6 `EditorView` via `view.editor.cm`. The public `Editor` type does not expose `cm`, so use `// @ts-expect-error` as documented by Obsidian (https://docs.obsidian.md/Plugins/Editor/Communicating+with+editor+extensions).
   - Read `editorLivePreviewField` safely with `state.field(editorLivePreviewField, false)` so it returns `undefined` instead of throwing when the field is absent (e.g., reading view or non-CM editor).
   - Keep immutable `setViewState` updates; only mutate the cloned state.
2. **Guard async transitions**
   - Add a class field tracking the in-flight `Promise<void>` from `setViewState`.
   - In `cycleViewModes`, ignore or await the pending promise before starting a new transition to prevent rapid-trigger races.
3. **Align compilation targets**
   - Change `tsconfig.json` `target` from `ES6` to `ES2018` to match `esbuild.config.mjs`.
4. **Clean up ESLint setup**
   - Remove inactive `.eslintrc`.
   - Add `"lint": "eslint ."` to `package.json` scripts.
5. **Harden `version-bump.mjs`**
   - Write `manifest.json` and `versions.json` to temp files and `fs.renameSync` atomically.
6. **Fix dev dependency vulnerabilities**
   - Run `npm audit fix`.
   - Verify `npm run build` and `npm run lint` still pass.
7. **Update `README.md`**
   - Minimal refresh.
   - State command name accurately: "Cycle view modes (reading / live preview / source)".
   - Mention it only affects the active Markdown editor.
   - Keep installation/usage, hotkey, Commander button, and CSS snippet sections.
   - Keep credits.
8. **Update `types.d.ts` or remove it**
   - Since the public API covers needs, remove the empty augmentation file.
