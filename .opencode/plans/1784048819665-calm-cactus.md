# Obsidian Cyclist Plugin — Fix Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans.

**Goal:** Fix all identified bugs, vulnerabilities, and brittle config in the Cyclist plugin while preserving the existing toggle command behavior.

**Architecture:** Keep the single-file plugin structure; replace private/global config mutation with per-leaf state changes, scope the command to the active leaf, and harden metadata/config tooling.

**Tech Stack:** TypeScript, Obsidian API, esbuild, eslint, npm.

---

## Global Constraints
- No `main.js` hand edits; generated by esbuild only.
- Keep plugin in `main.ts`; avoid new runtime dependencies.
- `package.json` version must stay at `0.0.1` unless `npm version` is run.
- Preserve command name "Cycle view modes (reading / live preview / source)" unless user wants rename.
- Plugin must still cycle all open markdown leaves if that is intended behavior; verify with user during implementation if ambiguous.

---

## Issues Found

1. **Functional:** Command ID repeats plugin ID (`main.ts:8`) — eslint `obsidianmd/commands/no-plugin-id-in-command-id` error.
2. **Functional/UX:** `setConfig('livePreview', ...)` mutates global user preference on every toggle (`main.ts:64`).
3. **Functional/UX:** `iterateAllLeaves` toggles every markdown leaf, not just active (`main.ts:66-68`). Likely surprising; should act on active leaf only.
4. **API risk:** `viewState.state` mutated in place with no fallback for unknown modes (`main.ts:38-51`).
5. **API risk:** `getCurrentMode` falls back to `'source'` for unknown modes (`main.ts:23`), breaking cycle if Obsidian adds modes.
6. **API risk:** `Vault.setConfig`/`getConfig` are private Obsidian API augmentations (`types.d.ts:4-7`) and may break.
7. **Config fragility:** Hand-rolled `ConfigItem` union in `types.d.ts` is incomplete and will drift with Obsidian updates.
8. **Tooling:** `versions.json` contains corrupt `"undefined": "0.15.0"` entry (`versions.json:3`) from `version-bump.mjs` run outside `npm version`.
9. **Tooling:** `version-bump.mjs` reads `process.env.npm_package_version` which is `undefined` when run directly; also `process` is not declared in module env.
10. **Tooling:** `@types/node ^25.0.3` is a non-existent/LTS-odd version; `obsidian: "latest"` is non-reproducible (`package.json`).
11. **Tooling:** `eslint.config.mjs` ignores `main.js` incorrectly inside an object, causing lint on generated file and possible crashes.

Change `main.ts:32` signature and body to deep-copy state before mutating:
```ts
private setViewMode(leaf: WorkspaceLeaf, mode: ViewMode) {
    const viewState = leaf.getViewState();

    if (viewState.type !== 'markdown') return;
    if (!viewState.state) return;

    const nextState = { ...viewState.state };

    switch (mode) {
        case 'reading':
            nextState.mode = 'preview';
            nextState.source = false;
            break;
        case 'live-preview':
            nextState.mode = 'source';
            nextState.source = false;
            break;
        case 'source':
            nextState.mode = 'source';
            nextState.source = true;
            break;
        default:
            return;
    }

    void leaf.setViewState({ ...viewState, state: nextState });
}
```

- [ ] **Step 5: Harden getCurrentMode fallback**

Change `main.ts:23` from:
```ts
return 'source'; // fallback
```
to:
```ts
return 'source';
```
(and keep; because no other Obsidian modes exist yet). Add an explicit assertion/skip if `view.getMode()` is not `'preview'` or `'source'`.
Refactor `getCurrentMode`:
```ts
private getCurrentMode(view: MarkdownView): ViewMode {
    const mode = view.getMode();

    if (mode === 'preview') return 'reading';
    if (mode === 'source') {
        const state = view.getState();
        return state?.source === false ? 'live-preview' : 'source';
    }

    return 'source';
}
```
OK as-is. Document fallback is a defensive default.

- [ ] **Step 1: Guard against missing npm_package_version**

Modify `version-bump.mjs`:
```js
import { readFileSync, writeFileSync } from 'fs';
import process from 'process';

const targetVersion = process.env.npm_package_version;

if (!targetVersion || targetVersion === 'undefined') {
    console.error('This script must be run via `npm version`. npm_package_version is not set.');
    process.exit(1);
}

let manifest = JSON.parse(readFileSync('manifest.json', 'utf8'));
const { minAppVersion } = manifest;
manifest.version = targetVersion;
writeFileSync('manifest.json', JSON.stringify(manifest, null, '\t'));

let versions = JSON.parse(readFileSync('versions.json', 'utf8'));
versions[targetVersion] = minAppVersion;
writeFileSync('versions.json', JSON.stringify(versions, null, '\t'));
```

## Risks & Notes

- **Behavior change:** Scoping toggle to active leaf changes long-standing behavior. If user actually wants all leaves to toggle, revert Step 3 of Task 1.
- **Private API removal:** Dropping `Vault.setConfig` may subtly change how Live Preview setting persists. If Obsidian requires global config to switch to live preview, this may need a different public API. Verify manually in Obsidian.
- **Command ID rename:** Existing hotkeys bound to old command ID may be lost; user should rebind after update.
